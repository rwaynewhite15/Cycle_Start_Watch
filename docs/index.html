Cycle Start Watch

A small, read-only Bluetooth logger for Fanuc, Okuma and Mori Seiki CNCs. It watches the cycle start lamp, records exactly when each machine is in cycle, and a Raspberry Pi gateway collects everything into one database. No ladder changes, no network, about an hour to install.

RUN: lamp on STOP: lamp off BLINK: lamp flashing OFF: machine unpowered

What it measures

The share of scheduled time each machine spends in cycle, shift by shift, plus every stop with its length. It is deliberately called in-cycle % rather than uptime or OEE availability: it knows when the control is executing a program, not why a machine stopped or how many good parts it made.

4

wires

Two across the lamp, two for 24 VDC power. All in parallel with existing wiring; nothing is cut.

0

ladder changes

No PMC, parameter or program edits. A controls engineer only reads the drawings.

ms

timestamps

Each RUN/STOP change is logged in UTC to the millisecond, from a battery-backed clock.

5 min

collection

A Raspberry Pi syncs every device in Bluetooth range every five minutes. No plant network needed.

How it works

The device senses the lamp through an optocoupler, logs state changes to flash, and serves them over Bluetooth Low Energy. The gateway pulls them into SQLite. Data leaves the Pi on a USB stick or a laptop cable.

Read-only by design

The device cannot start a machine or block a start, and that is guaranteed by the hardware, not just the software.

  • Input only. The only connection to the machine's signals is the LED side of an optocoupler. No relay or output is wired toward the machine.
  • Parallel tap. New conductors land beside the existing lamp wires. Nothing is disconnected or rerouted.
  • Single-fault safe. Two series resistors limit the draw to about 7 mA (under 20 mA if one fails shorted), with a 63 mA fuse at the tap.
  • Isolated power. An isolated DC-DC converter keeps the device's ground separate from the machine's 0 V.
  • Fully reversible. Pull two fuses, remove four wires, and the machine is as it was.

Why the lamp?

The button's contacts only say a start was pressed. The lamp follows the control's "in cycle" signal, so it gives run time.

Lamp behaviour comes from the machine builder's ladder, so each model is surveyed before install. Fallback signal: the green stack light.

A filter built for real lamps

A plain 200 ms debounce assumes a clean DC signal. Real lamps are messier, so the firmware cleans the signal in three stages. All three are unit-tested on a PC.

1 · Pulse stretch

AC lamps and PWM-dimmed LEDs switch the opto on and off hundreds of times a second. Any "on" in the last 25 ms counts as on.

2 · Debounce, 200 ms

Ignores glitches: noise from spindle drives, contact bounce, a lamp-test flash.

3 · Settle + blink

A change is logged once it has held for 1.5 s, and back-dated to when it began. A lamp that keeps flashing is logged as BLINK, not hundreds of RUN/STOP records.

The gateway

One Raspberry Pi per area of about 6–10 machines. No plant network: it keeps time with a battery clock and sets every device's clock on each sync.

  • Downloads only new records; storing the same record twice is harmless.
  • Logs every sync, including any records lost before collection.
  • Shift reports handle overnight shifts and daylight-saving changes.
  • Plain SQLite: query it directly or open it in DB Browser or Excel.

Installing one machine

About an hour for a qualified electrician, after a one-time survey per machine model.

  1. Survey. Watch the lamp through each machine state and find its terminals on the drawings.
  2. Lock out. Plant LOTO procedure; the cabinet carries 480 VAC.
  3. Wire four conductors. Lamp A through a 63 mA fused terminal, lamp B, +24 V through a 0.5 A fuse, and 0 V.
  4. Mount the device outside the steel cabinet so Bluetooth can get out.
  5. Test. Run, feed hold, M30. Confirm cycle start still works and no alarms appear.
  6. Pair with the gateway using the passkey on the device label.
